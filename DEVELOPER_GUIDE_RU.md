# Руководство разработчика Seeding (RU)

Дата актуализации: 20.02.2026

## 1. Назначение

Проект `Seeding` — дипломный прототип настольного приложения на `PyQt5` для анализа сеянцев:

- загрузка изображений и PDF;
- детекция сеянцев;
- классификация частей (соцветие/стебель/корень);
- измерения в `px` и `мм` после калибровки;
- экспорт результатов и PDF-отчёты.

Главный принцип текущей ветки: сохраняем рабочий функционал и читаемость кода, не перегружаем архитектуру.

## 2. Структура кода

Базовые модули пакета `seeding/`:

- `main.py` — точка входа и запуск GUI.
- `config.py` — константы и настройки по умолчанию.
- `models.py` — dataclass-модели состояния (`OriginalImage`, `ObjectImage`, `AllClassImage`, `AppState`).
- `controllers.py` — оркестрация ключевых сценариев через `AppController`.
- `services.py` — сервисы обработки изображений, экспорта и отчётов.
- `storage.py` — кэш и история измерений.
- `report.py` — сборка PDF.
- `utils/geometry.py` — геометрия (`bbox`, повороты, клиппинг).
- `utils/paths.py` — утилиты путей и валидации.

UI-модули в `seeding/ui/`:

- `main_window.py` — главное окно и пользовательские сценарии.
- `settings_dialog.py` — настройки, модели, калибровка, тема, язык.
- `tree_widget.py` — дерево слоёв и контекстные действия.
- `statistics_panel.py` — сводная статистика + экспорт CSV.
- `thumbnails_panel.py` — миниатюры для навигации.
- `export_dialog.py` — выбор форматов экспорта.
- `i18n.py` — runtime-словарь переводов `ru/en`.
- `theme_manager.py`, `styles.py` — применение QSS-тем.

## 3. Запуск и окружение

Минимальные требования:

- Python `3.10+`;
- Windows/macOS/Linux.

Установка:

```bash
python -m pip install -e .
python -m pip install -r requirements-dev.txt
```

Запуск:

```bash
python -m seeding.main
```

Тесты:

```bash
python -m pytest tests
```

## 4. Локализация и тема

- Все новые UI-строки добавляются через `tr(language, key, fallback)` в `seeding/ui/i18n.py`.
- Для runtime-переключения языка используется `self.current_language`.
- Для стилей используются QSS-файлы:
  - `seeding/resources/styles/dark.qss`
  - `seeding/resources/styles/light.qss`

Рекомендация: при добавлении новой кнопки сразу задавать:

- понятный ключ перевода;
- tooltip/status-tip;
- иконку из `seeding/resources/icons/`.

## 5. Правила правок

- Не менять поведение без необходимости.
- Любую новую публичную функцию описывать docstring на русском.
- Не дублировать логику: выносить повторяемые куски в приватные helper-методы.
- Для сообщений пользователю использовать `_show_info_message`, `_show_warning_message`, `_show_error_message`.
- Для новых операций над изображением сначала обновлять `AppState`/`image_storage`, затем перерисовывать UI.

## 6. Критические smoke-сценарии после изменений

1. Открыть файл -> запустить детекцию -> проверить отображение bbox.
2. Классифицировать объект -> проверить части в дереве.
3. Добавить/удалить часть через контекстное меню -> проверить обновление дерева и статистики.
4. Добавить/удалить сеянец -> проверить canvas, дерево и статистику.
5. Измерить линейкой -> сохранить запись в историю.
6. Калибровка из настроек -> измерение в мм начинает считаться корректно.
7. Экспорт статистики в CSV и генерация PDF-отчёта.

## 7. Частые причины регрессий

- несогласованность индексов после удаления элементов из дерева;
- обновление только canvas без пересборки дерева;
- строки в UI добавлены напрямую, без `i18n`;
- падения в фоновых сценариях из-за отсутствующих диалогов прогресса;
- конфликтующие стили QSS при ручных inline-стилях.

## 8. Что не делать перед защитой

- не запускать крупную декомпозицию `main_window.py`;
- не добавлять тяжёлые подсистемы без необходимости для демо;
- не менять формат хранения данных и кэша без миграционного плана;
- не усложнять UI новыми экспериментальными экранами.

Главный ориентир: стабильный прототип с чистым кодом и воспроизводимыми сценариями.
